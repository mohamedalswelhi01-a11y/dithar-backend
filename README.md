# باك اند متجر دِثار

باك اند حقيقي (Node.js + Express + PostgreSQL) لمتجر العبايات، يغطي:
تسجيل الدخول (JWT)، الفئات (قابلة للإضافة بلا حدود)، المنتجات والجرد
(معروض / نفذ الكمية / مؤرشف)، السلة، المفضلة، الطلبات، الدفع الإلكتروني
(هياكل جاهزة للبوابات الليبية)، المحفظة الإلكترونية، المرتجعات، ولوحة
إحصائيات الأدمن.

## 1) التشغيل محليًا
```bash
npm install
cp .env.example .env      # عدّل القيم (خصوصًا DATABASE_URL و JWT_SECRET)
npm run migrate           # ينشئ كل الجداول في قاعدة البيانات
npm run dev                # يشغّل الخادم على http://localhost:4000
```
يتطلب تثبيت PostgreSQL محليًا أو استخدام قاعدة بيانات سحابية (أدناه).

## 2) النشر الفعلي (لأن هذه المحادثة لا تستطيع استضافة خادم عام)
اختر أحد المسارين:

**أ) قاعدة بيانات سحابية جاهزة (الأسهل):**
- Supabase أو Neon أو Railway Postgres — أنشئ قاعدة بيانات مجانية،
  انسخ رابط الاتصال (`DATABASE_URL`) وضعه في `.env`.

**ب) استضافة الخادم:**
- Railway / Render / Fly.io: ارفع هذا المجلد كمشروع Node، أضف متغيرات
  البيئة من `.env.example`، شغّل `npm run migrate` مرة واحدة ثم `npm start`.
- أو VPS ليبي/خارجي عادي: ثبّت Node.js 18+ و PostgreSQL، ثم نفّذ نفس
  خطوات التشغيل المحلي، واستخدم `pm2` لإبقاء الخادم يعمل باستمرار.

بعد النشر، اربط واجهة المتجر (ملف `store.html` الذي بنيناه سابقًا) بهذا
الباك اند عبر تغيير رابط الطلبات من بيانات وهمية إلى:
`fetch('https://your-domain.com/api/products')` وهكذا لكل مسار.

## 3) بوابات الدفع الليبية — تكامل حقيقي عبر MyPay
بدل التكامل المنفصل مع كل بنك، الباك اند مربوط بـ **MyPay (mypay.ly)** —
مجمّع دفع ليبي موحّد يغطي بطاقة مصرفية، Edfali، سداد، موبي كاش، ياسر
باي، صحارى باي ومصرفي باي بحساب تاجر واحد. الكود في
`src/services/mypay.js` و `src/routes/payments.js`.

**لتفعيله:**
1. افتح حساب تاجر على mypay.ly واحصل على `Client ID` و `Secret ID`
   وسر الـ Webhook.
2. ضع القيم في `.env`: `MYPAY_ENV` (`sandbox` للتجربة ثم `production`)،
   `MYPAY_CLIENT_ID`، `MYPAY_SECRET_ID`، `MYPAY_WEBHOOK_SECRET`،
   و`PUBLIC_BACKEND_URL` (رابط الباك اند العام بعد نشره).
3. من داخل لوحة MyPay، اضبط رابط الـ Webhook على:
   `https://your-backend-domain.com/api/payments/webhook`

عند إتمام الشراء بأي طريقة غير الكاش أو المحفظة، يستدعي المتجر
`/api/payments/initiate` ويحوّل الزبون تلقائيًا لصفحة الدفع المستضافة
من MyPay، ثم يؤكد الطلب تلقائيًا عبر الـ webhook الموقّع (HMAC) بعد
نجاح الدفع — الدفع عند الاستلام والمحفظة الإلكترونية لا يحتاجان بوابة
خارجية ويُتمّان فورًا.

## 4) عناوين الشحن، صفحة تفاصيل المنتج، البحث والفئات
- `GET/POST/PUT/DELETE /api/addresses` — دفتر عناوين لكل زبون؛ الزبون
  يختار من عناوينه المحفوظة عند الدفع بدل كتابتها كل مرة.
- الضغط على أي منتج في المتجر يفتح صفحة تفاصيل كاملة (وصف، سعر، مفضلة).
- الضغط على أي فئة يفلتر المنتجات المعروضة لتلك الفئة فورًا، وهناك
  صندوق بحث أعلى الصفحة (`GET /api/products?search=`).

## 5) رفع صور المنتجات والبانرات
`POST /api/uploads` (أدمن فقط، `multipart/form-data` بحقل `image`) يرفع
صورة ويعيد رابطها، وتستخدمه لوحة التحكم مباشرة عند إضافة منتج أو بانر.
⚠️ التخزين محليًا على القرص افتراضيًا — على استضافات بحاوية مؤقتة مثل
Railway قد تُحذف الصور عند كل إعادة نشر. للإنتاج الجاد، استبدل التخزين
بخدمة تخزين سحابي (Cloudflare R2 أو Amazon S3) بنفس واجهة `src/routes/uploads.js`.

## 6) الواجهات الأمامية (frontend/)
- `frontend/store.html` — متجر الزبون، مربوط فعليًا بكل الـ APIs (وليس بيانات وهمية).
  يقرأ البانر العلوي والألوان واسم المتجر مباشرة من لوحة التحكم عند كل تحميل.
- `frontend/admin.html` — لوحة تحكم الأدمن الكاملة، بما فيها تبويب
  **"العرض والتسويق"**: إدارة شاشة الدعاية العلوية (إضافة/تفعيل/إيقاف/حذف
  بانرات، صورة، عنوان، رابط)، ألوان الهوية (الأساسي، التمييز، الخلفية)
  عبر منتقي ألوان، اسم المتجر وأيقونة الشعار، ورقم واتساب/الهاتف — أي
  تغيير يُحفظ في قاعدة البيانات ويظهر فورًا في متجر الزبون دون الحاجة
  لتعديل أي كود.
- `frontend/config.js` — غيّر `API_BASE` إلى رابط الباك اند بعد نشره.

⚠️ **هام:** هذان الملفان عاديان (HTML+JS) تستضيفهما على أي استضافة ثابتة
(نفس سيرفر الباك اند، أو Netlify/Vercel/Cloudflare Pages مجانًا) — لا
تفتحهما كـ Artifact داخل محادثة Claude، لأن صفحات Claude المنشورة
ممنوعة من الاتصال بأي خادم خارجي لأسباب أمنية على مستوى المنصة.

## 7) إنشاء أول حساب أدمن
التسجيل عبر `/api/auth/register` ينشئ حساب "customer" دائمًا. لترقية
أول حساب أدمن نفّذ مباشرة على قاعدة البيانات بعد التسجيل:
```sql
UPDATE users SET role = 'super_admin' WHERE email = 'your@email.com';
```

## 8) خريطة المسارات (API)
| المسار | الوصف |
|---|---|
| `POST /api/auth/register` `/login` | تسجيل حساب / دخول |
| `GET/POST /api/categories` | الفئات (إضافة فئات جديدة من الأدمن) |
| `GET/POST/PUT /api/products` | كتالوج المنتجات |
| `GET /api/products/admin/all?status=` | جرد: معروض / نفذ / مؤرشف |
| `PATCH /api/products/:id/archive` `/restore` | أرشفة منتج أو إعادته |
| `GET/POST/PUT/DELETE /api/cart` | السلة |
| `GET/POST /api/wishlist/:productId` | المفضلة (تبديل بالقلب) |
| `POST /api/orders` | إتمام الشراء من السلة |
| `GET /api/orders` `/admin/all` | طلباتي / كل الطلبات (أدمن) |
| `PATCH /api/orders/:id/status` | تحديث حالة الطلب |
| `POST /api/payments/initiate` `/webhook/:provider` | الدفع الإلكتروني |
| `GET/POST /api/wallet` `/topup` | المحفظة الإلكترونية |
| `POST /api/returns` `/admin/all` | المرتجعات |
| `GET /api/admin/dashboard` | إحصائيات لوحة التحكم |
| `GET/POST/PUT/DELETE /api/banners` `/admin/all` `/:id/toggle` | شاشة الدعاية العلوية |
| `GET /api/settings` `PUT /api/settings/:key` | الألوان والهوية والتواصل (theme / identity / contact) |

كل مسار أدمن محمي بالتحقق من `role = admin` في التوكن (JWT).
